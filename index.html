📱 فريق Flutter (سعيد، بسنت، سارة، محمود)

عاش جداً على التصميمات المبدئية. إحنا معانا براح لحد شهر 1 عشان نسلم الـ UI النهائي، فالتارجت بتاعنا الأسبوع ده خطوة بسيطة عشان نبني الأساس صح بدون ضغط.

(ملحوظة من محمود: يا سارة وبسنت، لو حد فيكم دخل في الـ Figma ولقى نفسه شاطر فيه وحابب يكمل كـ UI/UX Designer، مفيش مشكلة هنحوله بالكامل لـ UI، وأنا هشيل منه كل شغله في كود الـ Flutter).

🤝 أسئلة نقاش جماعية (تناقشوا فيها قبل الشغل)

  • يعني إيه State Management وليه منقدرش نستغنى عنها؟ (إزاي الداتا بتتنقل من شاشة لـ شاشة بدون ما تضيع).
  • إيه الفرق بين الـ Stateless والـ Stateful Widgets؟ (إمتى نستخدم دي وإمتى دي).
  • إزاي Flutter بيكلم الباك إيند؟ (يعني إيه REST API وإزاي بنستقبل الـ JSON).

📌 توزيع المهام الفردية

👤 سعيد (Team Leader) - بيئة العمل
1. كريت مشروع Flutter جديد.
2. قسّم الفولدرات بنظام Clean Architecture.
3. ارفع البروجكت على GitHub وضيف التيم.
4. جهز ملفات الألوان والخطوط (Theme).
👤 بسنت - تطبيق العميل
1. افتحي المشروع بعد ما سعيد يرفعه.
2. حولي شاشة واحدة بس (Login أو Splash) لـ Widgets.
3. اتأكدي إن الشاشة متجاوبة (Responsive).
👤 سارة - لوحة تحكم الشركة
1. اعملي الـ Scaffold الأساسي للوحة.
2. صممي القائمة الجانبية (Sidebar) اللي فيها زراير التنقل.
👤 محمود - تطبيق الفني
1. بناء الهيكل الأساسي للشاشة الرئيسية.
2. إضافة شريط التنقل السفلي (Bottom Navigation).
⚠️ أسئلة متوقعة من المعيد (جهزوا إجاباتها):
  • لـ سعيد: ليه اخترت الـ State Management دي بالذات ومستخدمتش غيرها؟
  • لباقي التيم: إزاي بتضمنوا إن الـ UI ميبقاش بطيء على الموبايلات الضعيفة؟

⚙️ فريق Backend (جيمي، تميم)

عاش يا شباب على الـ Schema وتدفق الـ Escrow. قدامنا لشهر 1 عشان نخلص الـ DFD والـ Schema بشكلهم النهائي، فالأسبوع ده هناخد خطوة تسخين برمجي.

🤝 أسئلة نقاش جماعية (تناقشوا فيها قبل الشغل)

  • يعني إيه RESTful APIs وازاي بنبنيها؟ (إزاي الموبايل بيبعتلنا Request وإحنا بنرد عليه).
  • إيه هو الـ Entity Framework وليه بنستخدمه؟ (ليه Code-First أفضل من كتابة SQL يدوي؟).
  • يعني إيه Escrow System برمجياً؟ (إزاي بنعمل Status للفلوس إنها "مجمدة").

📌 توزيع المهام الفردية

👤 جيمي - إعداد السيرفر وقاعدة البيانات
1. كريت مشروع ASP.NET Core Web API.
2. سطّب Entity Framework.
3. اكتب الكود الخاص بجدولين بس (مثلاً Users و Orders) كـ Models.
👤 تميم - تصميم الـ APIs للـ Escrow
1. امسك الـ Flowchart بتاع الفلوس.
2. حدد إحنا محتاجين كام Endpoint (للدفع، للتحويل، للاسترجاع).
3. اكتبهم في ملف وورد بسيط.
⚠️ أسئلة متوقعة من المعيد (جهزوا إجاباتها):
  • لـ جيمي: ليه استخدمت Code-First Approach بدل Database-First؟
  • لـ تميم: لو السيرفر وقع والعميل بيدفع، إزاي هتضمن إن الفلوس متتخصمش في الهوا؟ (ابحث عن ACID Transactions).
⏳ الديدلاين: السبت 17 أكتوبر 2026

🧠 فريق الذكاء الاصطناعي (جوسيان، زياد، توني، أحمد)

تنويه مهم: إحنا عدلنا الخطة وهنستخدم Gemini API بدل ما ندرب Model من الصفر. ده هيوفر تكلفة ووقت الأجهزة وهيطلع مخرجات أدق.

🤝 أسئلة نقاش جماعية (تناقشوا فيها قبل الشغل)

  • يعني إيه API وازاي هنستخدم Gemini؟ (إزاي بنكلم سيرفرات جوجل نبعتلها صوره وترد بالتحليل).
  • يعني إيه Dummy Data وليه بنستخدمها؟ (ليه بنألف بيانات وهمية بدل ما نستنى بيانات حقيقية).
  • يعني إيه Prompt Engineering؟ (إزاي بنجبر الذكاء الاصطناعي يرد بصيغة JSON تناسب الباك إيند).

📌 توزيع المهام الفردية

👤 جوسيان - بيانات الصيانة التنبؤية
1. افتحي شيت إكسيل.
2. اعملي أعمدة (تاريخ التركيب، ساعات الشغل، تاريخ العطل).
3. املي 10 صفوف بأرقام منطقية نجرب بيها الموديل.
👤 زياد - اختبار الصوتيات
1. ادخل على Google AI Studio.
2. ارفع ريكورد صوتي بيشرح عطل.
3. اكتب Prompt يحلل المشكلة وشوف النتيجة يدوياً.
👤 توني - اختبار الصور
1. ادخل على Google AI Studio.
2. ارفع صورة حقيقية لكسر أو عطل.
3. اطلب منه في الـ Prompt يرجع الوصف في صيغة JSON.
👤 أحمد - محرك التوجيه الذكي
1. ورقة وقلم واكتب خطوات اللوغاريتم (Pseudo-code).
2. حدد إزاي هتحسب المسافة.
3. إزاي هتدخل الـ Trust Score في الاختيار للترجيح بين الفنيين.
⚠️ أسئلة متوقعة من المعيد (جهزوا إجاباتها):
  • لـ جوسيان: إيه أهم المتغيرات (Features) اللي بتأثر فعلاً في التوقع؟
  • لـ زياد وتوني: إزاي نضمن إن الـ API دايماً هيرجع JSON سليم وميضربش Error؟
  • لـ أحمد: لو 3 فنيين على نفس المسافة ونفس التقييم، السيستم هيختار مين وليه؟
⏳ الديدلاين: السبت 17 أكتوبر 2026

📊 فريق البيانات والأمن (سيد، تامر)

شغلكم هو اللي هيقفل السيستم ويخليه آمن ومنطقي للشركات كـ B2B.

🤝 أسئلة نقاش جماعية (تناقشوا فيها قبل الشغل)

  • إيه هي الـ Edge Cases وليه لازم نختبر بيها؟ (ليه بنحط أرقام متطرفة جداً في الـ Trust Score).
  • يعني إيه Data Isolation؟ (إزاي نضمن إن شركة مستحيل تشوف بيانات شركة تانية).

📌 توزيع المهام الفردية

👤 سيد - محلل البيانات
1. افتح شيت الإكسيل اللي سلمته.
2. زوّد العمليات لـ 20 أو 30 عملية.
3. حط أرقام متطرفة (فني ممتاز وفني سيء) واتأكد إن المعادلة مبتطلعش أرقام سالبة.
👤 تامر - الأمن السيبراني
1. راجع الـ Schema بتاعت جيمي.
2. راجع الـ Flowchart بتاع تميم.
3. طلّع 3 ثغرات أو ملاحظات أمنية محتملة واكتبهم في ملف وورد.
⚠️ أسئلة متوقعة من المعيد (جهزوا إجاباتها):
  • لـ سيد: على أي أساس حددت الأوزان (النسب) في معادلة الثقة؟
  • لـ تامر: إزاي نمنع موظف في شركة صيانة إنه يخترق السيستم ويشوف بيانات منافس؟
